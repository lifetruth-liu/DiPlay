# P2 原型出口故障实验

范围是原生 echo 与独立 Android Linux 内核 TCP 客户端。工具只由 CMake 构建，
不链接进 Android.mk 产品库；默认后端和栈配置没有改变。此记录补充 N04 相关机制，
不是双向随机故障、真实 USB/NCM、生产 JNI 端点或 G2 性能验收。

## 故障规则

测试出口固定256槽，每帧最多1514字节。连同1024槽重复提交观测、熵和元数据，
整个port通过编译期断言限制在512KiB。输入立即复制；满队列返回not-ready，
不动态扩容。纯测试6项覆盖容量/绕环、复制、deadline、丢弃、重排、重复和非法长度。

| 配置 | 精确规则 |
| --- | --- |
| faults-1 | 每第100个接纳的Ethernet帧丢弃 |
| faults-5 | 每第20个接纳的Ethernet帧丢弃 |
| 两配置的延迟 | 非丢弃帧以提交时单调时钟加5ms排队，deadline前不写出 |
| 两配置的重排 | 每第10帧若存在排队前帧，与它交换；被丢弃或没有前帧时不交换 |
| 两配置的复制 | 每100帧中第50帧写两次，与周期性丢弃错开相位 |

因此并不声称随机1%/5%损失、精确10%乱序或精确1%复制分布；实际计数如下。
范围是整个出口Ethernet帧，含控制报文，不等于TCP数据段的故障比例。
重复包共用同一槽，第二次完整write才计数；失败/短写不出队。
等待使用head deadline与core timer的较小值，尚未到期时不监听POLLOUT。

## 结果

环境：任务AVD Android9/API28 x86_64，Linux4.4.124+，WHPX，两核/2GiB；
工具NDK28.2/API24。每行独立内核客户端TCP三次64KiB，内容、顺序和长度均通过。
客户端按绝对位置生成字节；故障场景不执行要求无损的UDP回显。

| 模式/配置 | 接纳帧 | 丢弃 | 延迟调度 | 排队交换 | 额外完整写出 |
| --- | ---: | ---: | ---: | ---: | ---: |
| TAP faults-1 | 236 | 2 | 234 | 18 | 2 |
| TAP faults-5 | 260 | 13 | 247 | 10 | 3 |
| veth faults-1 | 204 | 2 | 202 | 16 | 2 |
| veth faults-5 | 246 | 12 | 234 | 7 | 2 |

echo退出时若任何一种故障计数为零则失败；脚本要求客户端与echo均正常退出。
无故障TAP基本互通、veth十秒暂停后1MiB完整恢复也通过，注入计数全部为零。
终态lwIP heap peak约36KiB只覆盖该heap，不是整个后端内存或PSS。

额外veth faults-5抓包保存到build/reports/lwip/wire-faults5.pcap。
仅抓包观察到的重复TCP载荷数与人工复制数量相同，不能直接当作栈重传证据：
出口故障会在进入线缆/内核之前丢掉首次提交，抓包看不到它。
因此另用固定1024项观测接纳的native输出中相同peer/seq/长度/载荷hash的再次提交，
人工重复write不经过该计数。最终veth faults-5观察到10次重复提交、2次人工复制。
这是有界工作集估计，哈希碰撞、淘汰和分段变化可能影响它，不是完整TCP MIB统计。

## 验证与限制

Linux ASan/UBSan +lwIP heap/pool guards、Windows各25项通过；Android工具运行
四种配置通过。完整Android CI及APK检查见[实施记录](execution-status.md)。
新工具不依赖Android tc；此前netem不可用的事实保持记录。
尚未验证UDP故障归因、双向随机损失、长时负载或精确统计分布。
调度和观测开销存在于本工具，不能把此结果当作低配ARM core延迟基准。
