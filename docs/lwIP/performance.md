# 性能基准与资源预算

## 1. 目标与解释

主要目标是扩大兼容范围，同时让低配车机持续播放时无明显额外 CPU、内存和延迟负担。以下数字是开发初始验收预算，不是现有测量结果。P0 保存基线，P2 做可行性决策，P6 在目标车机验收；放宽预算必须单独评审并附证据。

性能结果必须区分协议栈微基准、USB 搬运和完整媒体会话。只优化桌面 iperf 数字可能掩盖车机解码/GC/USB 争用。

## 2. 初始预算

| 指标 | 初始门槛 | 测量条件 |
| --- | --- | --- |
| 吞吐余量 | 无损链路稳定承载实测媒体峰值的 1.5 倍；物理 USB 不足则不通过该配置 | Linux 对端 TCP/UDP 微基准，至少 10 分钟；与真实媒体峰值对照 |
| 核心处理延迟 | 排除 USB 等待及业务消费后，输入提交至应用队列 p95 ≤ 2 ms、p99 ≤ 5 ms | 目标低配车机、稳态负载；单调时钟打点 |
| 额外媒体排队 | 每通道健康稳态 p99 ≤ 10 ms，不随运行时间增长 | 满足吞吐预算时；不计缓冲音频自身约定缓冲 |
| CPU 增量 | 完整会话总 CPU 相比 VPN 增量 ≤ 10 个“单核百分比”点 | 100% 表示占满一个核，不按整机核数归一；同机同负载 A/B/A |
| 后端动态内存 | 新后端专属受控缓冲/端点分配峰值 ≤ 16 MiB | 不含解码器、媒体业务缓存与 so 静态映射；所有池和队列均计入 |
| 整体 PSS 增量 | 相比 VPN 稳态增量 ≤ 24 MiB | 同机同负载，包含 native 库/栈附加成本 |
| 启动耗时 | 后端准备 p95 ≤ 500 ms；完整连接 p95 相对 VPN 增加 ≤ 1 s | 不含用户交互、MFi 外部服务等待；分别报告，不掩盖总耗时 |
| 正常关闭 | 后端 stop 至本地资源回收 ≤ 2 s | 不等待对端 FIN ACK；全控制器清理另列 |
| 异常关闭 | USB 故障/超时后本地后端收敛 ≤ 5 s | 不要求恢复已拔出的硬件；不能 free 活对象 |
| 长稳泄漏 | 8 小时内 live native 对象无净增长；预热后 PSS 增长 ≤ 4 MiB 且无持续上升趋势 | 结合对象计数、每小时中位值；单独的 PSS 波动不直接认定泄漏 |
| 稳态质量 | 10 分钟无注入试验中后端自身 UDP 丢弃为 0，无新增音频 underrun | 背景应用和温控条件一致，源端/USB 丢失单独归因 |

G2 原型必须通过吞吐、core 延迟、16 MiB 上限和关闭预检；尚无完整媒体集成时 CPU/PSS 增量只作预测并注明，不能替代 G6 完整会话验收。设备温控降频、Full-Speed 带宽限制需单独报告，不能跨设备比较平均数。

## 3. 内存配置起点

lwIP 的 PCB、segment、pbuf、send buffer 与接收窗口相互影响，应从峰值带宽与往返时延计算窗口，再测量，不能全部按最大值配置。

| 预算项 | 初始上限 | 行为 |
| --- | --- | --- |
| 活动 TCP 连接 | 32 | 超限拒绝新连接；现有流与关闭命令仍可运行 |
| UDP 端点 | 32 | 超限返回 RESOURCE_LIMIT |
| listen 端点 | 16 | 支持动态通道，超限明确失败 |
| 重组上下文 | 4，累计负载 ≤ 256 KiB，超时 ≤ 30 s | 超限/超时丢弃并计数；依据固定版 lwIP 能力实现 |
| 入口/出口帧排队 | 各 ≤ 512 KiB | 有界唤醒和回压，溢出按类型计数 |
| 所有应用 TCP 接收缓存 | 累计 ≤ 4 MiB | 按消费速度更新窗口，不无限预取 |
| 所有发送缓存 | 累计 ≤ 2 MiB | 业务写者等待或 deadline 失败；关闭可取消 |
| 所有 UDP 接收缓存 | 累计 ≤ 512 KiB | 实时媒体还受时间预算限制；丢过期报文 |
| 待处理业务命令 | ≤ 1024 条 | 控制/关闭预留独立配额，饱和仍可停止 |

这些分类是总 16 MiB 的子预算，不可把未列出的 lwIP heap、pool、DirectByteBuffer、元数据和线程相关分配排除。P2 提供预算汇总和实际分配峰值，若固定版本无法直接表达全局上限，适配层必须实现准入与计数。

零拷贝不是第一阶段目标。先采用明确所有权的一次复制，再根据热点减少；不得通过借用已释放 pbuf 或固定 Java 数组获得虚假的性能提升。

## 4. 实验方法

1. 固定提交、APK、编译选项、设备、固件、iPhone、USB 数据口和线缆；记录电源、温度、CPU 频率及后台负载。
2. 分别执行 VPN(A)、lwIP(B)、VPN(A)，每档预热 2 分钟、测量至少 10 分钟，独立重复 3 组。顺序可轮换，保留全部结果。
3. 用低/常用/最高支持的视频配置，分别运行音乐、导航、Siri 和通话混合负载；不能仅播放静止画面。
4. 测 TCP 单流、双向流、多通道 TCP+UDP；注入 0/1/5% 丢包和不同 RTT。无损预算与故障恢复结果分表。
5. 汇总 p50/p95/p99/max、标准化 CPU 单位、内存峰值/趋势和丢弃原因，不仅报告均值。
6. 采集负载前后线程、FD、live handles、pbuf、租约计数；长稳报告每小时中位值。

Linux 对端可使用 TAP/veth 和测试 echo/load generator；不要求 iPhone 上存在 iperf 服务。真实 iPhone 会话单独采集完整媒体指标。宿主 benchmark 脚本不能被描述成车机性能自动验收。

## 5. 观测点

使用同一单调时钟域在设备内记录：USB 完成、帧提交、core 开始/结束、应用队列交付、业务消费、TX 入队/USB 完成。跨 Linux/iPhone 时钟的单向延迟未经同步不能直接相减。

- core：唤醒次数、单次工作量、最长执行时间、timer lateness、队列水位。
- TCP：有效吞吐、重传、窗口零值时长、应用等待、发送 backlog。
- UDP：接收/发送/截断/超限/过期/来源拒绝计数，按通道区分。
- USB：NTB 大小/帧数、读写时间、not-ready、短写、重组/resync。
- 资源：lwIP heap/pool 使用、DirectByteBuffer 租约、端点数、JNI 引用及线程/FD。
- 媒体：已有接收统计、音频 underrun、可用的解码/显示帧指标；不能只看网络收包数。

诊断以周期聚合和直方图为主，不逐包打印。使用 `adb shell dumpsys meminfo <package>`、`adb shell top`、Perfetto 或设备支持的等效工具采样；ADB 仅用于开发测量，日常功能不得依赖它。工具权限不可用时标明可测指标，不编造缺失数据。

## 6. 调优顺序与停止条件

先定位 USB 等待、核心阻塞和窗口背压，再减少重复分配/JNI 往返，之后才调整批处理、TCP 窗口和拷贝。批处理必须同时限制字节数与等待时间，不以吞吐换取音频/控制延迟。

所有调优对照同一基准，并重跑关闭、丢包和资源测试。出现崩溃、UAF、静默数据损坏、无限队列或音频明显退化时停止优化，先恢复正确性。若目标低配车机持续不达标，保持实验状态或限制支持配置，不自动提高媒体缓冲掩盖问题。
